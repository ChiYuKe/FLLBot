# agent

## 连续聊天与工具

群人格保存后用于后续新消息；正在处理或已进入会话快照的任务保留原设定。
通用 Agent 规则管理参与边界、工具权限与执行事实；身份、称呼和语气以当前人格为准，不沿用历史回答中的旧人格。
切换人格不会删除群历史或其他群的设置；模型表现仍取决于人格内容与所用模型的指令遵循能力。

聊天、查资料和文件等工具任务使用同一流程；不需要先选择聊天／任务模式，已授权工具在首轮即可见。
“为什么”“继续”“改成 MD 文件”等追问结合近期对话、直接引用与已有执行结果理解；多位群友的任务仍分别处理。
普通首轮不额外请求任务摘要模型；上下文较长的工具任务和真实溢出仍按预算处理，不删除工具定义来提速。
工具有部分失败、未发送或结果不确定时，应说明未完成部分，不将整批当作成功或自动重发成功内容。
这些规则帮助模型正确处理，但不能保证所有自然语言追问都不误判，实际响应速度仍受模型服务影响。

## 静默参与

自动参与时，判断无需接话应调用内部 `agent__stay_silent`，不会向群发送“我不接话”等决策说明。
该动作不属于外部插件权限；模型未启用工具能力或工具轮数已用尽时，使用内部标记 `<NO_REPLY>` 静默结束。
静默时不会保存一条虚假的 Bot 回复，用户原话仍按群聊记忆规则保留。正常询问“不接话的原因”仍可回答。

## 自动参与判断

自动参与（未被 @、未用唤醒词）会先经过确定性评分：被 @、唤醒词、提问、接话、图片等提高分数，
纯语气词、复读、刷屏、Bot 刚刚连续发言等降低分数。低于 `participation_threshold`（默认 -10，
可在群设置覆盖）时直接跳过模型请求，只在“消息追踪 → 触发决策”记录原因；`-100` 关闭筛选。
评分不读历史正文，计数器按账号与群隔离、重启清零。明确叫 Bot 的消息始终不会被这一层过滤，
是否开口仍由模型的 `agent__stay_silent` 决定。

## 工具发现与效率

工具由宿主目录统一登记：插件没有变化时复用同一份工具快照和模型定义，只有本群可见的工具才会复制 Schema。
执行时只解析目标工具并实时复核授权，避免每次调用都重建整份目录。同一轮里相同参数的纯读取调用会复用
结果；带写入/发送/管理能力或挂了工具钩子的调用不会缓存。插件开发者约定见 `docs/tool-registry.md`。

## 工具沙盒

插件工具声明 `capabilities` 和 `risk` 后，执行前由宿主按 `[sandbox]` 策略裁决能力、路径、链接、
发起者权限、自动参与边界和本轮额度。被拒绝时工具返回 `tool_blocked`，不执行回调，也不产生外部动作。
自动参与时不会执行写入或群管理类操作；需要群友明确请求。工作区文件与联网走 `ctx.sandbox`，
细节见 `docs/agent-sandbox.md`。

## 群聊记忆

“聊天设置 → 群聊记忆”默认开启近期原文与话题压缩：当前连续对话最近 200 条，工作上下文预算 24000 字符，
同时受模型窗口约束。启用 Agent 的群中，未触发回复的普通消息也会被记录并按需发给模型作为背景；
不会因此增加插话。间隔超过 30 分钟默认开启新对话，旧话题不自动续接。

较早原文按话题生成带来源的摘要，原始记录仍保存在本地。摘要失败不删原文，不循环压缩旧摘要。
只有当前用户提及过去或引用消息时，才开放本群原文查询工具；可按关键词、日期查找，并分页查看相邻回答。
记忆按机器人账号与群隔离，清空群聊天历史也会清空原文和摘要。关闭记忆时沿用原来的历史限制。

在群级设置中启用后，智能体会读取普通群消息，让模型判断是否需要回复或调用工具。模型只会收到启用该功能后的会话历史。群聊历史中的用户消息会带上发送者标签 `昵称(QQ号，身份)`，身份为群主 / 管理员 / 成员，模型据此区分不同成员的发言。

## WebUI 设置

- **模型接入**：配置模型服务地址、API Key 和模型名称；高级参数含回复上限、随机性、上下文与额外指令。默认人格在“人格库”独立管理。
- **群聊自然语言响应**：默认关闭。开启后，此群消息会发送给已配置的模型服务。
- **什么时候回复**：仅被 @、以 Bot 唤醒词开头，或读取普通消息交给模型判断。已有配置默认保留自动参与行为。自动参与还受阈值筛选和沙盒边界约束。
- **允许调用的工具**：逐个勾选工具（如「语音朗读」「联网搜索」「天气查询」）；模型只会获得这些插件用 `on_ai_tool(...)` 注册的工具。

默认参数从“配置 → 默认行为”管理；群聊范围和独立策略从“配置 → 群聊设置”管理。模型服务与人格库作为独立资源供策略选择。

模型服务需要兼容 OpenAI Chat Completions 的 `tools` / `tool_calls` 格式。内置 `basic` 插件提供只读工具 `basic__check_online`。

唤醒词可在“机器人”页面自行填写，留空时使用 Bot 昵称。例如唤醒词为“小助手”，发送“小助手，你好”即可；只发送“小助手”时也会自然回应。自定义唤醒词不会随账号昵称同步而改变。

单群配置的回复条件可多选，按“或”组合。@、唤醒词、自动参与任一满足即处理，同一条消息只调用一次智能体；选中自动参与时也会处理普通消息。
正文以唤醒词开头时可以不 @ Bot；仅在句子中间提及唤醒词不会按唤醒词触发。
消息开头若明确 @ 其他群友，则不参与，即使后续正文以唤醒词开头；QQ 引用回复标记与空白不会遮挡这个判断。
正文先用唤醒词叫 Bot、再 @ 其他成员的操作请求仍可正常响应。


## 长任务控制与进度

群任务按“机器人账号＋群＋发起者”隔离：同一个人的消息按顺序处理，不同群友可以同时执行。默认全局消息处理并发、单群并发和模型请求并发均为 6；超过名额的任务排队，排队超时仍按配置生效。已有显式模型并发设置继续保留；启用群级费用或 Token 额度时，模型请求沿用额度保护的串行结算机制。

启动配置 `[plugin]` 中 `max_concurrency` 控制全局事件处理数，`max_concurrent_per_group` 控制单群并行人数，`max_pending_per_conversation` 现在限制每位发起者的排队数；修改这些启动字段需要重启。`[llm].max_concurrency` 控制模型请求数，单个模型服务可以另外指定更低上限。

任务发送到原群的文字分段和工具媒体会引用原消息，没有可引用消息时 @ 发起者；合并转发内容也会标明接收者。其他群友的消息仅作为背景，当前任务只处理当前发起者的请求和补充。

长回复仍优先按“自动／合并转发／分段”设置发送。合并转发被协议明确拒绝时，完整内容会排版成一张 Markdown 长图发送，不再回退成大量普通文字分段；代码块、标题和表格使用共享排版器。图片也无法生成时，只发一条简短提示。转发超时或没有有效回执时，送达结果不确定，不自动补发图片。显式选择“分段”仍保留原有分段行为。

任务执行期间，发起者可以在同一账号、同一群发送：

- `/任务进度`：查看当前步骤和阶段，不再调用模型。
- `/任务取消`，或直接说“取消任务”“停止任务”“不用做了”：停止后续模型和工具操作，不撤回已执行动作。
- `/任务补充 新要求`，或“补充：新要求”“修改要求：新要求”“改成：新要求”：在下一个安全边界应用补充。每条最多 4000 字，最多同时等待 8 条。
- 任务发起者也可以在同一群里直接 @ 机器人发文字追问。机器人会先回复当前执行阶段，再在当前模型请求或工具步骤结束后处理追问。

控制消息在普通消息入队之前处理，因此同群长任务不会阻塞取消或补充。仅控制发送者自己的活动任务，不跨账号、群或用户选择目标。进入结果发送阶段后不再接收补充；需要新任务时等发送结束后再提出。没有自己的活动任务时，普通自然语言不会被强行识别为控制命令；显式命令会提示没有任务。

补充到达时，正在请求的模型结果不会直接发出；尚未启动的旧工具调用会记录为跳过，已经执行的工具结果保持不变。执行中的工具收到取消后，可能已经产生外部动作，仍按实际情况记录为成功、失败或结果不确定，不能通过重新运行来补救。

管理端“消息追踪 → 聊天轮次”中可刷新查看每一步的模型请求、工具状态、重复提醒与上下文整理记录。数据库只保存进度元数据，不保存该记录中的提示词、补充正文、工具参数或模型内部推理。

同一工具、相同规范化参数连续调用 3、5、8 次及后续每 8 次会向模型追加提醒，要求复用已有结果、调整方法或说明限制。即使模型换了调用 ID，仍能识别重复；提醒不会禁止合理的再次查询。

任务上下文达到可用输入预算的 80% 后，会尝试把较早的完整对话及工具批次整理成任务摘要，保留原始目标、补充要求和最近批次。摘要是当前任务的背景资料，不是新的系统指令。摘要失败时可缩减工具结果正文，保留调用与结果配对。明确的上下文超限只在实际缩减后重试一次模型请求，不重新执行工具；认证、参数等其他错误不会触发此恢复。无法缩减原始输入或系统规则时仍会报告原错误。

任务整理不替代群聊长期记忆，也不提供进程重启后的自动续跑；重启仍保留中断事实，不重做已执行动作。

## 提示词缓存

固定 Agent 规则和插件策略排在可能含当前时间、提问者等变量的人格内容之前；工具列表按名称排序，工具 schema 的对象键使用稳定顺序。这样可以复用更多相同的请求前缀。当前时间、用户信息和工具权限仍按原有设置提供，不通过放宽白名单或缓存旧答案提高命中。

“用量统计”显示整体及各模型的输入缓存命中率，“聊天轮次”显示单次请求的命中 Token。统计来自服务商返回的 `prompt_cache_hit_tokens`，也兼容 `prompt_tokens_details.cached_tokens`。只对报告缓存数据且输入用量有效的请求按 Token 加权；未报告与零命中分开显示。旧记录保留为未知，费用估算目前仍按配置的输入单价计算，不单独计算缓存折扣。

服务端缓存是否命中还受模型服务、工具集合、历史窗口、缓存构建时间及服务商保留策略影响，不保证固定比例。这里优化的是提示词前缀复用，每次回答仍会重新生成。

## 插件包维护

元信息以 [plugin.toml](plugin.toml) 为准，开发约定见 [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md)，更新记录见 [CHANGELOG.md](CHANGELOG.md)。

工具调用持续到智能体完成任务，不设置轮数或单轮数量限制；旧版 max_tool_rounds 设置不再生效，运行时也不再接受失效的 max_rounds 参数。整轮会话受统一截止时间约束；取消任务、会话失效及单个工具超时仍会中止相应操作。

执行前会校验整批调用结构，拒绝重复或无效 ID；缺少 ID 时统一补齐，执行记录与发给模型的消息共用同一 ID。结构异常的批次不会执行其中任何工具。参数错误返回字段路径与约束，便于模型修正，不返回原始参数值。工具权限仍以执行时的实时配置为准；有副作用的操作超时后记录为结果不确定，不自动重试。
