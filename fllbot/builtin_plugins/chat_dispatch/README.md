# 聊天调度

内置插件 `chat_dispatch` 默认启用。模型在生成最终回复时根据用户要求、内容和单条消息长度，选择普通消息或 QQ 合并聊天记录。普通回复预计产生三条或更多消息，或者两条消息会分开发送含代码块的正文时，插件改用合并聊天记录。

用户未指定格式时，模型也会从当前会话已授权的工具中选用适合的交付方式。比如查询武汉明天的天气时，优先调用天气卡片工具查询并发送预报。卡片不可用时可用已授权的查询工具取得数据后用文字作答。

自动模式下，含 Markdown 表格的普通回复会在分段前尝试排版成一张图片。合并聊天记录则把每张表渲染成独立图片，前后的文字保持原来的顺序。用户需要纯文字或可复制的 Markdown 时保留表格原文。某张表排版失败时，该表保留为文字。

用户明确要求直接发文字时优先发送普通消息。QQ 明确拒绝模型调度的合并转发后，正文按普通消息分段补发。

可在插件管理中全局或按群关闭。关停后，发送方式回到聊天设置，明确的文字要求仍然生效。

## 群聊好友申请

在群聊的智能体设置中启用自然语言响应，并在「允许调用的工具」勾选「向当前发言者申请 QQ 好友」(`chat_dispatch__request_friendship`)。群友可以发「@Bot 可以加我好友吗」。模型根据当前消息判断意图，协议端的目标由真实 QQ 群消息的发送者确定。同一个 Bot 对同一个用户每分钟最多尝试一次。

主动申请需要协议端实现扩展动作 `send_friend_request`，参数为 `user_id` 和 `message`，成功回执为 `status: "ok"` 和 `retcode: 0`。标准 NapCat 的公开 API 未提供这个动作；收到不支持的回执时，Bot 会引导群友通过群成员资料向它申请。申请已提交后，由用户在 QQ 中接受。

## 自动同意好友申请

在「插件管理 → 聊天调度 → 配置」开启「自动同意好友申请」。此全局开关默认关闭，保存后对 FLLBot 中启用的 QQ 账号生效。用户可直接向 Bot 提交 QQ 好友申请，FLLBot 收到带有效 `flag` 的好友请求事件后，会通过 NapCat 的 `set_friend_add_request` 同意。整个流程无需提前在群里发消息或调用模型。

功能只处理 NapCat 上报的好友申请，入群申请和入群邀请照常处理。近期重复上报的同一申请会按 Bot 账号和申请标识去重。
