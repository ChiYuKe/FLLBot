# FLLBot 后端管理规划

日期：2026-11-02。性质：基于当前仓库的设计建议，未代表功能已实现。

## 1. 定位与现状

面向本地自托管、一个维护者管理多个 QQ 机器人和多个群的控制台。沿用 FastAPI、asyncio、SQLite 和内置 WebUI，兼容 QQBot 桌面宿主嵌入与浏览器独立使用。

现有基础包括连接管理、机器人默认值、群覆盖、插件与工具、模型与人格、会话和用量、日志、就绪检查、管理令牌、数据库备份及离线恢复。规划重点是统一这些能力的管理流程，再补充任务、诊断和变更追踪。

本轮根据源码与文档静态梳理，未启动真实 QQ、模型或语音服务；现有文档可能随正在进行的改动更新。

## 2. 管理对象与规则

| 对象 | 管理内容 | 关系 |
| --- | --- | --- |
| 实例 | 监听、存储、日志、管理凭据 | 单个 FLLBot 进程 |
| 机器人 | QQ 身份、连接、昵称、唤醒词、默认行为 | 一个实例可连接多个机器人 |
| 群/私聊 | 准入、触发、回复、资源引用、会话 | 与机器人共同确定执行场景 |
| 模型服务 | 接口地址、密钥、模型、超时、单价 | 多个场景共享 |
| 人格 | 提示词、变量、版本、引用关系 | 由默认设置或场景引用 |
| 插件 | 加载、启停、配置、错误、依赖 | 提供命令、事件处理、任务或工具 |
| 工具 | 来源插件、用途、权限、授权范围 | 启用插件不等于授权 AI 调用 |
| 任务 | 提醒、定时推送、运行记录 | 执行时重新检查场景权限 |

行为继承统一为：系统默认 → 机器人默认 → 群覆盖。界面同时展示原始值、最终值和来源。

权限单独计算：全局停用、群禁止访问、插件不可用等硬限制不能通过下层行为配置绕过。最终执行还须满足触发条件、用户权限和工具授权。

明确四种不同操作：停用群、禁止群访问、移除群覆盖、清理群数据。移除覆盖只恢复继承，不删除历史和插件数据。

当前群配置以 group_id 为主，同一群的覆盖对多个机器人共享；现有群记忆已有 self_id 隔离，而聊天历史等表采用不同作用域。第一阶段保留现有群策略语义并在页面明示；第二阶段审计所有会话、任务、用量和插件状态的隔离键。若增加“某机器人在某群的专属设置”，引入 (self_id, group_id) 覆盖层，优先于共享群覆盖，不能静默改变旧数据含义。

## 3. 页面规划

保留已有导航入口与旧链接，按任务组织内容，逐步调整栏目名称。

| 栏目 | 主要内容 | 首要操作 |
| --- | --- | --- |
| 概览 | 在线账号、可服务群、模型用量、异常与就绪状态 | 处理异常、继续初始化 |
| 机器人 | 账号列表、连接诊断、唤醒词、机器人默认值 | 同步账号与群、查看不回复原因 |
| 群聊与规则 | 群列表、准入、群开关、触发方式、模型/人格/工具覆盖 | 批量修改、查看最终配置 |
| AI 资源 | 模型服务、人格库、对话测试 | 测试连接、查看资源引用 |
| 插件与工具 | 插件列表、声明式配置、工具目录、授权范围 | 启停、重载、配置、授权 |
| 任务中心 | 提醒、定时推送、执行记录、失败原因 | 暂停、取消、受控重试 |
| 数据与诊断 | 会话、群记忆、调用链、日志、用量 | 查失败原因、清理指定数据 |
| 系统设置 | 默认行为、权限、连接参数、备份、存储与维护 | 修改全局配置、创建备份 |

群列表建议支持“全部已发现群 / 有单独配置的群 / 异常群”视图，避免未配置的群看起来不存在。群详情按基本、AI、工具与插件、记忆、诊断分区；默认只展开常用项。

模型和人格删除前展示引用位置，提供更换引用或取消删除。插件配置由 schema 渲染，新增插件不要求修改宿主页面。TTS 等外部服务先展示健康状态、超时和错误，服务进程生命周期交由明确的部署方式或桌面宿主负责。

## 4. 三条关键流程

### 首次接入

连接账号 → 测试模型 → 选择人格 → 允许一个测试群 → 选择回复方式 → 验证就绪状态。模型测试明确标记“不发 QQ、不执行工具、会产生模型调用”；真实群测试必须选中目标并由用户点击发送。

### 配置一个群

选择机器人视角和群 → 查看最终配置及来源 → 修改覆盖 → 展示影响范围 → 保存并查看生效结果。普通单字段可以自动保存，复杂弹窗整体保存；统一提供保存中、已保存、失败和冲突状态。

### 排查一次不回复

检查连接 → 准入 → 群开关 → 触发 → 插件 → 模型配置与调用 → 工具 → QQ 发送。每一层返回可读原因、稳定原因码、相关设置入口，区别“配置齐全”和“实际连通”。

## 5. 后端职责与 API

沿用现有分层，API 做鉴权与校验，策略模块计算最终行为，服务层组织操作，storage 管理持久化和迁移，插件实现具体业务。

优先抽取配置修改、权限计算、诊断和备份等共用操作，供通用 API 与 console API 共同调用。不要为了目录整齐一次性拆分全部模块，也不要在前端复刻权限规则。

建议逐步补充的契约：

- 最终配置响应：value、source、overridden、blocked_reasons、requires_restart。
- 配置写入：PATCH + revision；服务端校验成功并持久化后返回最终值。过期版本返回冲突，避免多个窗口互相覆盖。
- 列表：统一筛选与游标分页；日志和事件流有缓冲上限、断线后重新拉取状态。
- 批量修改：预览影响范围，明确事务边界与每项结果，失败不得伪装为全部成功。
- 诊断：记录 trace_id，串联消息接收、策略判断、模型调用、工具调用和发送结果；默认不记录密钥与完整敏感正文。
- 长操作：备份、批量诊断等返回作业 ID，可查询状态；普通保存保持同步返回。
- 错误响应：稳定错误码、可读说明、字段错误、trace_id；复用现有路由并维持兼容期。

## 6. 数据与权限

继续使用 SQLite 与现有迁移机制，先补索引、保留策略和分页。新增明确需要查询的数据表，不把所有管理数据继续塞进 KV：

| 建议对象 | 用途 | 阶段 |
| --- | --- | --- |
| 配置修订与管理操作记录 | 谁修改了什么、影响范围、失败与回退依据 | 第一阶段 |
| 运行诊断记录 | 消息处理阶段、错误、耗时、关联调用 | 第二阶段 |
| 任务及运行记录 | 时间、时区、目标、状态、重试与发送结果 | 第三阶段 |

只有管理令牌时，操作主体记录为管理客户端或凭据标识，不能声称能识别具体个人。审计不保存密钥明文；密钥字段区分保留、替换和清空。

后台管理权与 QQ 使用权限分别管理。当前保留单管理员令牌；确需多人协作后再增加所有者、运维、观察者角色和账号会话，不提前建设多租户系统。

桌面嵌入与独立浏览器都应避免长期把管理令牌放进 URL；优先请求头，浏览器事件流可使用受控短时凭据或其他经过设计的认证通道。兼容已有接入方式时明确迁移过程。

数据库备份不等于完整实例备份：还需明确包含用户人格、配置、插件及其数据、外部服务配置的范围；导出默认不携带密钥。当前恢复保持停机流程，先验证、保留当前副本，再恢复；后台可以先提供备份列表、创建、下载和恢复指引。

消息、AI 上下文、群记忆、运行日志、调用记录分别定义保留期限。清理前预览范围与数量；清理后不得被摘要或缓存重新带回。费用保留“估算”标记，不承诺与供应商账单一致。

## 7. 实施顺序与验收

| 阶段 | 交付 | 验收标准 |
| --- | --- | --- |
| P0：规则统一 | 配置来源、权限原因、作用域清单、统一保存语义 | 两个窗口不会静默覆盖；多个机器人在同群时影响范围清楚；旧配置重启后保持语义 |
| P1：管理闭环 | 群列表与详情、机器人默认值、资源引用检查、管理记录 | 能完成首次接入、单群配置、移除覆盖和追查一次修改；常见不回复有明确原因 |
| P2：运行诊断 | 消息调用链、模型与外部服务健康、用量筛选、数据保留、备份入口 | 一次失败能定位到具体阶段；清理范围可核对；备份可在隔离实例验证恢复 |
| P3：任务管理 | 插件任务适配、运行记录、取消与重试 | 重启后状态可恢复；断线和权限变化有明确处理；不盲目重复发送消息 |
| P4：按需扩展 | 多人权限、远程访问、批量导入导出、更多统计维度 | 需求和部署边界明确后单独设计 |

每阶段完成一个可用流程再扩范围。验证优先覆盖配置继承、硬限制、重启持久化、多机器人作用域、并发修改与备份恢复；界面人工验证桌面嵌入和独立浏览器。规划阶段不修改运行配置或数据库。
