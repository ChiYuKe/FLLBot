# 管理后台

启动 FLLBot，在桌面端打开 FLLBot WebUI，或访问 `/ui` 并输入管理令牌。原来的令牌、模型和群配置继续生效。

后台沿用 QQ 桌面控制台的侧栏、灰黑卡片、主按钮、表单和字体设置。页面、文本框、列表和弹出菜单共用桌面滚动条的宽度、颜色与悬停样式。内嵌使用时同步桌面端当前主题、主题包、字体、紧凑布局和减少动画设置；主题变化不会重新加载后台。独立打开仍支持明暗切换和 `?theme=dark|light`。

全站统一使用侧栏、页面标题、范围提示、栏目标签、内容区和操作栏。页面标题下标明实例/账号/群/资源范围及保存方式；未保存的页面在侧栏显示提示点。群列表与开关即时保存，表单则明确要求点击保存。概览优先呈现运行统计，首次接入引导放在后方；模型、系统、账号和保留策略的主要保存操作置于表单前部。深浅主题沿用桌面配色，窄窗口自动收拢分栏。

## 页面结构

参考 AstrBot 的配置、资源与会话规则分层，侧栏包含概览、Agent、群与回复、模型服务、人格库、插件、Agent 工具、任务中心、数据与日志，系统设置放在侧栏底部。

- 群与回复：群聊设置 / 默认回复规则。只列出主动新增及已有的单群覆盖；其他群使用默认行为。常用项紧凑排列并自动保存，详细参数点击“编辑”。旧版群覆盖编辑器收在默认行为的折叠区。
- 模型服务：模型接入 / 对话测试。
- 插件：安装、启用和配置插件本身。
- 工具：插件显式开放给智能体的能力清单，显示来源插件、权限、默认是否开放和被多少群单独授权。
- 数据与日志：运行日志 / 会话记录 / 用量统计。

旧的 `#agent`、`#playground`、`#history` 等链接仍可直接打开对应标签；切换栏目保留表单草稿，并记住各栏目的当前标签。模型和人格是共享资源，群策略引用它们；单群覆盖的概念可参考 [AstrBot 自定义规则说明](https://docs.astrbot.app/use/custom-rules.html)。

## 第一次使用

概览新增“首次接入引导”：选择机器人视角、填写测试群号并刷新，按步骤检查连接、模型、人格、群准入和回复配置。该引导不自动开启群或发送测试消息；“必要配置检查通过”之后仍需到真实群发消息确认。模型实际连通性使用模型服务中的对话测试确认，测试会产生用量。

系统设置、模型设置和 Agent 聊天设置也支持旧版本冲突提示，保存失败时保留当前表单。重新读取会替换草稿；聊天设置有未保存修改时会先要求确认放弃。

1. 在**系统设置**复制反向 WebSocket 地址，填入 NapCat；令牌使用 `server.access_token`，消息格式选择 `array`，开启心跳。
2. 在**模型服务 → 模型接入**填写服务地址和 API Key，获取并选择模型。服务不提供模型列表时，点击“手动填写”。保存后测试连接。
3. 在**人格库**新建人格（人格库初始为空，程序不内置人格），填写提示词并保存，再点击“设为默认人格”。提示词旁的「说明」列出 `{bot_name}` 等可用变量。未设置人格时机器人使用兜底提示词。
4. 在**配置 → 群聊设置**点击“添加群配置”，选择需要单独设置的群；未添加的群使用默认设置。
5. 在**配置 → 群聊设置**直接选择该行的“回复方式”，修改后自动保存；唤醒词在“机器人”页面设置。默认行为可在旁边的标签中修改。启用 AI 回复后，匹配消息和会话上下文会发送给模型。
6. 在**模型服务 → 对话测试**检查模型和人格；此处只测试模型回答，不会发送 QQ 消息，也不会执行插件工具。

模型服务总开关、系统设置里的“允许群聊 AI 对话”、群访问范围和插件开关共同决定机器人能否回复。概览的就绪检查提供对应入口。

## 常用操作

**系统设置 → 备份与恢复**：创建数据库备份后显示作业状态，切换页面不会重复创建；刷新浏览器后可在同一会话继续查询。完成后可校验、下载或查看停机恢复指引。若进程已重启、旧作业查不到，刷新文件列表核对。数据库可能包含会话和密钥，下载时使用管理请求头，不把令牌放进下载链接。恢复必须先停止 FLLBot，页面只展示命令，不执行恢复。人格、插件文件和外部模型需要另外备份。

**系统设置 → 外部服务**：默认只展示已知状态；点击检查才调用插件声明的健康接口。语音插件显示 Qwen 与 IndexTTS 服务，并标明当前选用的后端。加载中或空闲卸载不等于服务故障；检查不会合成语音或主动加载模型。进程管理仍由原有部署方式或桌面宿主负责。

“数据与日志 → 消息诊断”按账号、场景、会话、消息 ID 和结果筛选消息处理记录，支持继续读取更早记录。点击一条记录查看阶段、耗时和原因码，例如未被 @、冷却中、模型主动沉默、工具无权限、队列溢出或发送失败。诊断是异步保存的，刚发生的消息可能需要稍后刷新；页面显示本次运行中诊断队列丢弃和写入失败计数。

详情中的“在近期运行日志中查找”按诊断 ID 筛选当前载入的运行日志；若日志已不在内存范围，需要查看日志文件。诊断表保留最近 7 天且最多 10000 条，每条最多 100 个阶段，后台不记录消息正文或调用参数。成功发送表示观察到调用成功，不保证最终送达或已读。

群聊设置只列出主动添加或已有单独配置的群；没有添加的群使用默认设置。可选择机器人视角查看不同账号继承后的状态；群配置仍共享，选择账号不会创建该账号专属覆盖。点击“添加群配置”后可修改该群的设置。

模型服务详情和人格编辑器提供“引用位置”，展示系统默认、路由/备用模型、机器人默认和单群覆盖的直接引用，不重复统计继承关系。引用入口可定位到群列表相应字段。人格仍被机器人或群引用时禁止删除，需先更换这些引用；只有系统默认引用时保留原有行为，删除前确认使用兜底提示词。

群详情、表格内编辑、准入和批量操作会携带读取时的设置版本。其他窗口先修改后，本次保存会提示冲突，不覆盖最新配置。详情弹窗保留当前草稿并停止重复提交，可先复制需要保留的内容，再点击“重新读取最新设置”；确认后放弃旧草稿。表格冲突后使用“刷新群列表”重新读取。

群详情新增“变更记录”，支持继续查看更早记录。只显示时间、对象与改动字段；全局配置记录单独标明可能影响本群，不代表该群一定发生行为变化。记录不含配置内容，当前不区分具体管理者。

在群详细设置中展开“生效详情”，可查看模型、人格、群聊响应、回复方式、唤醒词和工具等设置的实际来源，以及逐项不回复诊断。诊断使用已保存设置；修改后需先保存并重新打开详情。它区分配置就绪与账号在线，不会调用模型或发送测试消息；真实调用失败仍需查看运行日志。

### 设置某个群

进入“配置 → 群聊设置”：

1. 点击“新增配置”，选择需要单独设置的群并添加。未添加的群沿用默认行为。
2. 直接修改该行的“回复方式”“模型”或“人格”，等待“已保存”提示。
3. 需要工具权限、回复间隔、调用轮数或补充要求时，点击该行“编辑”，在弹窗里修改并保存；点击取消不保存草稿。

列表保存保留原有详细配置，不修改其他群。点击“移除”会清除这条单群覆盖（包括旧版智能体群覆盖），恢复默认行为；该群的准入也恢复默认，但保留其他群名单与其他插件配置。弹窗里的“生效详情”提供完整的继承和就绪说明。

群配置表不再设置“启用”或“访问”，也不提供访问权限批量操作。添加后按该群表单配置运行，未添加的群使用默认设置；点击“移除”恢复默认。旧版访问限制仍保留在后端配置中，不会因更新页面被清除。

“跟随默认设置”只恢复回复方式的继承，已设置的模型、人格、工具限制等仍保留；可在表格中分别把模型和人格恢复默认，工具等选项在编辑弹窗中恢复。已有后端访问限制和模型总开关仍然有效，工具执行仍遵守用户权限。

### 其他操作

- **调整回复长度**：模型服务 → 模型接入 → 高级参数。Token 上限和上下文长度是不同参数。
- **不同群使用不同人格**：配置 → 群聊设置 → 在该行选择人格。选择“跟随默认”会移除该群的人格覆盖。
- **配置插件与授权 Agent 工具**：插件管理负责启停插件和配置后端（例如语音插件选择 Qwen 或 IndexTTS）；Agent 工具负责授权模型调用插件提供的具体动作（例如 `voice__speak`）。一个插件可以提供多个工具，也可以不提供 Agent 工具。工具列表会标明来源插件；执行时仍检查插件状态与用户权限。
- **清理上下文**：数据与日志 → 会话记录 → 选择会话 → 清空此会话。此操作删除该会话全部 AI 记录，不能恢复。
- **排查不回复**：概览 → 就绪检查；然后查看运行日志。模型配置就绪表示参数已配置，实际连通性以模型测试结果为准。
- **查看消耗**：数据与日志 → 用量统计支持今天、7 天、30 天和全部时间。消息总量为累计收到的消息，与模型 Token 分开统计。费用按配置单价估算。

切换页面会保留编辑中的表单；页面顶部显示未保存提示，关闭或刷新页面时会提醒。切换同一页面中的群或人格会读取对应对象的配置，请先保存正在编辑的对象。

## 本地预览

运行 `.venv/Scripts/python.exe tools/preview_console.py`，打开 `http://127.0.0.1:6719/ui?token=console-preview-only&theme=light`。

预览使用 `.console-preview/` 的独立数据库与固定测试令牌，默认不启用模型，不连接 QQ。真实实例仍按原方式启动。


### 机器人与昵称唤醒

侧栏“机器人”展示已连接过的账号、昵称及在线状态。账号连接时自动通过 OneBot `get_login_info` 同步昵称，也可点击“同步账号与群聊”刷新。昵称暂时获取失败时保留该账号上次成功的昵称；未设置自定义唤醒词且从未获取昵称的账号不响应唤醒。

每个 Bot 可分别保存群聊默认回复方式、模型和人格。优先级为：单群覆盖 > Bot 默认设置 > 系统默认设置；全局模型、权限和访问范围开关仍有效。同一群的覆盖对群内所有 Bot 生效，未覆盖项目分别继承各自 Bot 默认值。

“听到唤醒词时回复”使用该 Bot 的自定义 `wake_word`，留空时使用账号昵称。例如设置为“小助手”，发送“小助手，你好”即可。只发送唤醒词（不带其他内容）时也会自然回应，不会静默忽略。自定义唤醒词不会被昵称同步覆盖，清空后恢复跟随昵称。旧群 `trigger_prefix` 兼容保留但不再用于匹配。

接口：`GET /api/console/bots`，`POST /api/console/bots/refresh`，`PUT /api/console/bots/{self_id}/defaults`（`reply_mode: inherit|at|prefix|all|off`、`wake_word`（最多 80 字，留空使用昵称）、`provider`、`persona`）。都需要管理令牌。群详情接口支持 `?self_id=` 查看指定 Bot 的实际继承结果。


群聊设置采用紧凑的单群配置表，只显示主动添加和已有覆盖的群。可搜索群名或群号，在列表中直接修改回复方式、模型和人格，修改后自动保存。“编辑”打开详细设置弹窗，填写 Agent 工具权限、回复间隔、自动参与概率与阈值、沙盒写入/联网/内网开关、调用轮数和补充要求；取消不会保存草稿。自动参与概率只影响普通消息，@ 和唤醒词触发不受影响；自动参与阈值低于设定分时不请求模型；沙盒开关留空继承全局 `[sandbox]`。表格保存只修改相应项目，保留已有详细配置。


单群“回复方式”支持同时勾选“被 @”“唤醒词”“自动参与”，点击“应用”后保存，任意一个条件满足即可响应；同时命中多个条件也只处理一次。消息开头 @ 的是其他账号时，视为在跟别人说话，智能体不参与；@ 全体或同时 @ 本 Bot 仍按原规则处理。“跟随默认”和“关闭 AI”与其他选项互斥。API 的 `policy.trigger_modes` 为非空列表（`at`、`prefix`、`all`），旧 `trigger_mode` 单选字段继续兼容；修改其他详细设置会保留已选组合。自动参与概率只作用于普通消息，@ 和唤醒词触发始终按原规则处理。


“Agent 工具”页面只管理模型可调用的具体动作权限，例如 `voice__speak`、`web__web_search` 和 `web__read_webpage`。每个工具都会标出来源插件；插件启停、Qwen / IndexTTS 后端和其他插件选项只在“插件管理”中配置。单群授权按具体工具 ID 设置，并继续遵守插件状态与用户权限。工具目录同时显示 `risk` 与 `capabilities`；实际执行还受 `[sandbox]` 能力开关、路径/主机范围、自动参与边界和本轮额度约束，可用 `GET /api/sandbox` 查看最近裁决。提供 Agent 工具的插件会同时出现在插件管理和工具权限中，前者管理插件包，后者管理模型调用入口；工具页不提供重复的插件配置入口。

### 数据保留与清理

系统设置 → 数据保留与清理，提供自动保留策略和手动清理。自动保留默认关闭，0 天表示该类别不自动清理；保存策略不会立即执行删除。策略保存支持版本冲突保护，切换页面保留草稿。

手动操作依次选择类别、天数与会话范围，点击“预览范围与数量”，核对各类数量后勾选确认并提交。修改范围会使当前预览失效；预览有效 10 分钟，单次最多 50000 条。预览后记录集合变化会停止清理，重新预览即可。清理在事务中执行，失败回滚；执行中可切换页面，通过结果区核对已提交的结果。页面刷新后尝试查询原作业，服务重启后以持久化结果为准，勿盲目重复提交。

AI 会话、群记忆原文与相关摘要一起处理；目前这些历史以及模型用量未按 Bot 独立保存，Bot 过滤仅支持消息记录和消息诊断。会话清理会使当前实例所有处理中会话的旧结果失效，可能需要重新发送消息；已发出的外部请求无法撤回。摘要的所有来源记录都必须仍存在才能保存。

清理不包含配置、插件 KV、任务、日志文件和已有备份。旧备份可能仍包含清理的数据。消息与用量统计反映保留的数据，清理后相应减少。删除后需借助已有数据库备份停机恢复；恢复是整库操作。

### 人格编辑冲突

人格为共享资源，保存后引用它的机器人和群会使用修改后的内容。编辑和删除会检查读取时的文件版本，新建不会覆盖其他窗口已经创建的同名人格。发生冲突时保留当前草稿；先复制需要保留的内容，再点击“重新读取”，对照最新内容修改后保存。重新读取前会提示放弃未保存的草稿。

人格保存采用完整写入后原子替换，原有 `.txt` 和自定义文件名就地更新。模型编辑继续使用全局配置版本，其他系统配置更新也可能导致模型保存提示冲突。引用仍通过“引用位置”跳转至对应系统、机器人或群设置逐项更换。

### 任务中心

“运行 → 任务中心”展示插件声明的任务来源，按来源、Bot、群/私聊、创建者和状态筛选并分页。当前 daily 插件适配提醒与待办；任务仍通过原有 Agent 工具创建。运行记录显示管理动作、等待条件和发送回执。未加载插件不展示来源，已加载但停用的插件仍可查看与暂停、取消任务。

暂停可恢复，取消/完成为终态；发送中的任务需等待回执。取消只阻止后续执行，不能撤回已发送消息。列表是快照，管理操作检查版本，冲突时先刷新核对。提醒时间展示为北京时间 UTC+08:00，运行记录时间使用浏览器本地时区。

断线、插件关闭或场景权限阻断会继续等待并记录原因。发送报错、中断或重启遗留 sending 状态会转为“送达不确定”，停止自动重发。确认后重试会明确提示目标和重复发送风险，实际执行仍检查连接与权限。任务和运行记录保存在插件数据库，主数据库备份不包含这些文件，备份实例时需另外包含 `data/plugins/daily/`。

### 批量更换模型或人格引用

在人格或模型服务的“引用位置 → 批量更换直接引用”中选择目标，点击“预览全部直接引用”，核对来源、目标、系统默认、机器人和群的范围，再勾选确认并提交。修改目标会废弃旧预览；预览有效 10 分钟，单次最多 1000 处。任意资源/配置变化会要求重新预览；写入失败整体回滚，不会只改一部分。

成功后原资源仍保留，源资源的直接引用变为零，目标资源可以查看迁移后的引用。群覆盖对同群多个 Bot 共享；从系统默认或机器人默认继承资源的场景随上层生效。处理中的模型请求可能仍使用旧资源。其他页面的草稿不会被静默替换，请重新读取受影响配置后继续编辑。模型与人格内容、密钥、群开关和历史不会被这个操作删除或更改。

### 配置作用域与插件保存

完整字段、代码默认值、归属、启动/新连接/后续请求生效边界，以及数据是否按 Bot 隔离，见 [作用域清单](admin-scope.md)。清单明确列出目前尚未通过验收的兼容字段和启动构造边界。

默认行为页及插件弹窗使用读取时的版本保存；其他窗口或后台群策略改变后会保留草稿并提示重新核对。保存期间锁定当前字段和作用域选择，失败后恢复编辑。多字段保存使用同一事务，全局/群项全部成功后才生效。密钥响应遮盖，表单留空保持既有密钥，API 可显式清空。

### 账号默认设置

Agent 页面保留原聊天参数，并增加“账号默认设置”标签。选择在线或离线账号后，维护默认回复方式、账号唤醒词、模型服务和人格；页面显示当前全局唤醒词是否优先。跟随实例、默认关闭 AI 和群单独覆盖的关系在表单中明示，保存不发送测试消息。资源引用里的机器人“前往修改”会定位到对应账号。

切换账号或重新读取前提示放弃未保存草稿。版本冲突保留字段内容，先复制需要保留的草稿，再重新读取核对。保存时锁定字段与账号选择，失败后恢复编辑。同步在线账号昵称不替换默认值，也不改变默认值版本。已失效模型/人格会保留原标识供核对，保存前必须更换为存在的资源。

### 启动参数只读区

系统设置增加“启动参数”，区分启动来源的配置值与已归档的旧覆盖。启动参数不可在线修改：需要调整监听、数据库位置、插件加载等，请修改启动配置文件或启动命令并重启。现有系统表单只保存运行时参数。旧历史覆盖保留供核对，不会在下次重启自动采用。

admin.enabled=false 关闭后台页面、管理 API、文档和事件流，机器人连接及健康检查保留；重新打开需本地修改启动配置。配置错误消息支持结构化原因说明，不显示服务器合并配置中的密钥。

### 全局插件停用

插件页开关控制实例默认状态。明确关闭显示“全局停用”，会阻止各群的新消息/工具处理及后续任务调度，群里单独开启无法绕过；群覆盖和数据保留，重新启用后恢复。插件仅声明默认关闭时，标签显示“默认关闭”，群单独开启仍可能生效。页面按实例默认状态筛选，不把声明默认关闭误标为全局硬停用。

开关操作携带版本，其他窗口或后台接口改变状态后会提示刷新核对。已经进入执行的操作可能继续，已发出的请求无法撤回；管理读取、配置检查和插件初始化仍可进行。插件开关变更记录与状态整体提交。


### 聊天轮次诊断

- `GET /api/console/turns`：按 `self_id`、`scene`、`scene_id`、`status` 筛选，支持 `before` 游标和 `limit`（1–200）。
- `GET /api/console/turns/{turn_id}`：返回轮次元数据、工具状态、分段回执，以及 `can_cancel`、`can_retry`。
- `POST /api/console/turns/{turn_id}/cancel`：取消当前进程中进行的轮次；返回 accepted 后通过详情查询终态。

以上接口沿用管理鉴权，不返回输入、候选正文、工具参数或结果。取消会阻止尚未开始的动作；
已经发生的外部动作保留原有执行/送达事实。发送中的取消仍可能形成 delivery_uncertain，不能宣称已经撤回。
终态或重启后不在当前进程运行的轮次返回 409；当前不提供整轮重试，避免重复已完成工具。


### 账号聊天开关

`PUT /api/console/bots/{self_id}/state`，请求 `{"enabled": false}` 停用账号聊天业务，
`{"enabled": true}` 重新启用。沿用管理鉴权和设置写入权限，可用 `If-Match` 提交账号 revision。
`GET /api/console/bots` 的账号条目包含 enabled；online 仍单独表示协议连接情况。

停用会取消进行中的聊天轮次，并使该账号此前接收的上下文和排队消息失效；重新启用不恢复旧任务。
停用状态持久化，不会修改群准入、插件开关或账号默认回复方式，也不会撤回已经发送的消息或工具动作。


### 明确未发送分段的恢复

`POST /api/console/turns/{turn_id}/recover-delivery` 仅恢复单个分段回复计划中 failed/pending 的分段；
要求失败轮次、原账号仍在线且启用、数据和账号代次未变化，并通过当前群/插件/原处理器权限复核。
只发送持久化正文，不调用模型或工具；成功和 uncertain 分段禁止重发。恢复中的状态通过同一详情接口查看。

协议响应缺少有效 message_id 时也属于送达不确定：请求可能已经被 QQ 执行，不能据此补发。
该分段不进入可见聊天历史，详情保留 InvalidDeliveryReceipt 错误类别；点赞等非消息动作不计入首次回复送达时间。
旧记录缺少恢复元数据、转发回复、已取消或存在不确定分段的轮次返回 409；当前管理面板仅为满足条件的轮次显示恢复按钮。
恢复发送超时后进入 delivery_uncertain，不再提供补发。已有群消息权限要求会在每段前重新查询成员身份。


`GET /api/console/trigger-decisions` 返回不含正文的触发决策，包含接受/忽略/拒绝、原因、触发方式与
有效策略版本，支持 `self_id`、`scene_id`、`before` 和 `limit`。未唤醒、冷却、概率跳过和访问拒绝
可独立查询；这些记录随 traces 数据集保留策略清理。


恢复格式补充：新计划保存完整引用和 @ 消息段，恢复不会采用后来修改的分段或格式配置。
若转发被明确拒绝并已降级，可补发降级路径中已知未发送的普通分段；不会重新发送原转发。
缺少完整格式元数据的旧记录不开放恢复。


### 调试轮次与只读账号视角

`POST /api/llm/chat` 结果包含 turn_id；轮次 entrypoint 为 admin_debug。
可传 self_id（默认 0）选择真实账号的只读历史视角，搭配 scene、scene_id、include_history。
真实账号调试禁止 save=true，默认不写会话、不执行工具、不发送 QQ；独立调试的显式 legacy 保存仍兼容。
管理页“对话测试”已使用该入口，支持查看本次轮次；调试中的任务可从轮次详情取消。


`GET /api/console/message-events` 提供接收和排队阶段元数据，支持 self_id、scene_id、before、limit。
记录包含事件键、轮次 ID、trace_id、接收时限、排队/处理终态和原因，不包含消息段或正文。
这些记录随 traces 保留策略清理；稳定消息键在记录保留期间用于跨重启去重，未完成记录重启后标为 cancelled。


容量说明：QQ 消息、管理调试和恢复发送共用会话容量账本，QQ 入队占用不会在开始模型轮次时重复计算。
调试容量不足返回 429；恢复容量不足也返回 429，不开始发送。直接调试等待会话锁也有排队截止时间。
`/api/status` 的 dispatcher.conversation_admission 包含 used、capacity、conversation_capacity 和 active_keys。


### 按账号查看和清空会话

会话目录条目包含 self_id；`GET/DELETE /api/chat/{scene}/{scene_id}` 使用 `self_id` 查询参数，默认 0 只处理
legacy/独立调试记录。群历史优先返回所选账号的群记忆，没有记忆时返回该账号聊天历史，source 表示来源。
清空仅删除所选账号在此会话的正文、记忆、候选和工具结果，已执行动作元数据保留。
清理预览的 conversations 数据集也支持指定 Bot；usage/changes 仍不支持账号过滤。


清理后的回执：会话清理擦除候选和分段正文，保留已发生的发送状态与消息 ID，轮次详情标记 bodies_cleared。
正在发送时清理，迟到的成功或不确定回执仍可记录；不会恢复正文或开启补发。清理预览不重复计算已擦除正文的计划。


关闭期间聊天调试和分段恢复返回 503（服务正在关闭），区别于容量不足的 429。
进行中的调试/恢复和 QQ 轮次会先取消并提交可追踪终态，再关闭数据库；发送中取消不保证没有送达，保留不确定回执。
