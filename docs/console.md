# 管理后台

启动 FLLBot，在桌面端打开 FLLBot WebUI，或访问 `/ui` 并输入管理令牌。原来的令牌、模型和群配置继续生效。

后台沿用 QQ 桌面控制台的侧栏、灰黑卡片、主按钮、表单和字体设置。页面、文本框、列表和弹出菜单共用桌面滚动条的宽度、颜色与悬停样式。内嵌使用时同步桌面端当前主题、主题包、字体、紧凑布局和减少动画设置；主题变化不会重新加载后台。独立打开仍支持明暗切换和 `?theme=dark|light`。

## 页面结构

参考 AstrBot 的配置、资源与会话规则分层，侧栏包含概览、机器人、配置、模型服务、人格库、插件、工具、数据与日志，系统设置放在侧栏底部。

- 配置：群聊设置 / 默认行为。只列出主动新增及已有的单群覆盖；其他群使用默认行为。常用项紧凑排列并自动保存，详细参数点击“编辑”。旧版群覆盖编辑器收在默认行为的折叠区。
- 模型服务：模型接入 / 对话测试。
- 插件：安装、启用和配置插件本身。
- 工具：插件显式开放给智能体的能力清单，显示来源插件、权限、默认是否开放和被多少群单独授权。
- 数据与日志：运行日志 / 会话记录 / 用量统计。

旧的 `#agent`、`#playground`、`#history` 等链接仍可直接打开对应标签；切换栏目保留表单草稿，并记住各栏目的当前标签。模型和人格是共享资源，群策略引用它们；单群覆盖的概念可参考 [AstrBot 自定义规则说明](https://docs.astrbot.app/use/custom-rules.html)。

## 第一次使用

1. 在**系统设置**复制反向 WebSocket 地址，填入 NapCat；令牌使用 `server.access_token`，消息格式选择 `array`，开启心跳。
2. 在**模型服务 → 模型接入**填写服务地址和 API Key，获取并选择模型。服务不提供模型列表时，点击“手动填写”。保存后测试连接。
3. 在**人格库**选择人格，点击“设为默认人格”。新建人格后需要分别保存内容和设为默认。
4. 在**配置 → 群聊设置**找到对应群，勾选“启用”；需要限制访问时，在表格顶部选择默认访问范围，并修改对应行的“访问”。
5. 在**配置 → 群聊设置**直接选择该行的“回复方式”，修改后自动保存；唤醒词在“机器人”页面设置。默认行为可在旁边的标签中修改。启用 AI 回复后，匹配消息和会话上下文会发送给模型。
6. 在**模型服务 → 对话测试**检查模型和人格；此处只测试模型回答，不会发送 QQ 消息，也不会执行插件工具。

模型服务总开关、系统设置里的“允许群聊 AI 对话”、群访问范围和插件开关共同决定机器人能否回复。概览的就绪检查提供对应入口。

## 常用操作

### 设置某个群

进入“配置 → 群聊设置”：

1. 点击“新增配置”，选择需要单独设置的群并添加。未添加的群沿用默认行为。
2. 直接修改该行的“启用”“回复方式”“模型”或“人格”，等待“已保存”提示。
3. 需要工具权限、回复间隔、调用轮数或补充要求时，点击该行“编辑”，在弹窗里修改并保存；点击取消不保存草稿。

列表保存保留原有详细配置，不修改其他群。点击“移除”会清除这条单群覆盖（包括旧版智能体群覆盖），恢复默认行为；该群的准入也恢复默认，但保留其他群名单与其他插件配置。弹窗里的“生效详情”提供完整的继承和就绪说明。

访问限制已合并到同一张配置表：顶部“默认访问”选择所有群可用或仅允许准入的群；每行“访问”选择默认、允许或禁止。旧白名单、黑名单自动显示为允许、禁止，名单里的其他群不会被单行编辑覆盖。禁止优先于默认访问。勾选表格中的配置行后，会显示批量允许、禁止和跟随默认操作；只更新所选群。

“跟随默认设置”只恢复回复方式的继承，已设置的模型、人格、工具限制等仍保留；可在表格中分别把模型和人格恢复默认，工具等选项在编辑弹窗中恢复。群总开关、表内访问规则和模型总开关始终有效，工具执行仍遵守用户权限。

### 其他操作

- **调整回复长度**：模型服务 → 模型接入 → 高级参数。Token 上限和上下文长度是不同参数。
- **不同群使用不同人格**：配置 → 群聊设置 → 在该行选择人格。选择“跟随默认”会移除该群的人格覆盖。
- **配置插件与授权 Agent 工具**：插件管理负责启停插件和配置后端（例如语音插件选择 Qwen 或 IndexTTS）；Agent 工具负责授权模型调用插件提供的具体动作（例如 `voice__speak`）。一个插件可以提供多个工具，也可以不提供 Agent 工具。工具列表会标明来源插件；执行时仍检查插件状态与用户权限。
- **清理上下文**：数据与日志 → 会话记录 → 选择会话 → 清空此会话。此操作删除该会话全部 AI 记录，不能恢复。
- **排查不回复**：概览 → 就绪检查；然后查看运行日志。模型配置就绪表示参数已配置，实际连通性以模型测试结果为准。
- **查看消耗**：数据与日志 → 用量统计支持今天、7 天、30 天和全部时间。消息总量为累计收到的消息，与模型 Token 分开统计。费用按配置单价估算。

切换页面会保留编辑中的表单；页面顶部显示未保存提示，关闭或刷新页面时会提醒。切换同一页面中的群或人格会读取对应对象的配置，请先保存正在编辑的对象。

## 本地预览

运行 `.venv/Scripts/python.exe tools/preview_console.py`，打开 `http://127.0.0.1:6719/ui?token=console-preview-only&theme=light`。

预览使用 `.console-preview/` 的独立数据库与固定测试令牌，默认不启用模型，不连接 QQ。真实实例仍按原方式启动。


### 机器人与昵称唤醒

侧栏“机器人”展示已连接过的账号、昵称及在线状态。账号连接时自动通过 OneBot `get_login_info` 同步昵称，也可点击“同步账号与群聊”刷新。昵称暂时获取失败时保留该账号上次成功的昵称；未设置自定义唤醒词且从未获取昵称的账号不响应唤醒。

每个 Bot 可分别保存群聊默认回复方式、模型和人格。优先级为：单群覆盖 > Bot 默认设置 > 系统默认设置；全局模型、权限和访问范围开关仍有效。同一群的覆盖对群内所有 Bot 生效，未覆盖项目分别继承各自 Bot 默认值。

“听到唤醒词时回复”使用该 Bot 的自定义 `wake_word`，留空时使用账号昵称。例如设置为“小助手”，发送“小助手，你好”即可。只发送唤醒词（不带其他内容）时也会自然回应，不会静默忽略。自定义唤醒词不会被昵称同步覆盖，清空后恢复跟随昵称。旧群 `trigger_prefix` 兼容保留但不再用于匹配。

接口：`GET /api/console/bots`，`POST /api/console/bots/refresh`，`PUT /api/console/bots/{self_id}/defaults`（`reply_mode: inherit|at|prefix|all|off`、`wake_word`（最多 80 字，留空使用昵称）、`provider`、`persona`）。都需要管理令牌。群详情接口支持 `?self_id=` 查看指定 Bot 的实际继承结果。


群聊设置采用紧凑的单群配置表，只显示主动添加和已有覆盖的群。可搜索群名或群号，在列表中直接修改启用、回复方式、模型和人格，修改后自动保存。“编辑”打开详细设置弹窗，填写 Agent 工具权限、回复间隔、调用轮数和补充要求；取消不会保存草稿。表格保存只修改相应项目，保留已有详细配置。


单群“回复方式”支持同时勾选“被 @”“唤醒词”“自动参与”，点击“应用”后保存，任意一个条件满足即可响应；同时命中多个条件也只处理一次。“跟随默认”和“关闭 AI”与其他选项互斥。API 的 `policy.trigger_modes` 为非空列表（`at`、`prefix`、`all`），旧 `trigger_mode` 单选字段继续兼容；修改其他详细设置会保留已选组合。


“Agent 工具”页面只管理模型可调用的具体动作权限，例如 `voice__speak`、`web__web_search` 和 `web__read_webpage`。每个工具都会标出来源插件；插件启停、Qwen / IndexTTS 后端和其他插件选项只在“插件管理”中配置。单群授权按具体工具 ID 设置，并继续遵守插件状态与用户权限。提供 Agent 工具的插件会同时出现在插件管理和工具权限中，前者管理插件包，后者管理模型调用入口；工具页不提供重复的插件配置入口。
