# email — QQ 邮箱发送

让智能体通过已配置的 QQ 邮箱，把群友需要的内容作为纯文本邮件发出去。

群里大多数人的邮箱就是 **QQ 号 + `@qq.com`**，所以工具允许直接填 QQ 号，插件会自动补成
`123456@qq.com`；不填收件人时，默认发给当前发言人自己的 QQ 邮箱，适合“把结果发我邮箱”这类请求。

## 准备

1. 登录发件 QQ 邮箱，进入「设置 → 账户」，开启 **SMTP 服务**，按提示生成 **授权码**。
2. 在 FLLBot 的「插件 → email」里填写：
   - **发件邮箱**：例如 `123456789@qq.com`
   - **SMTP 授权码**：上一步生成的授权码（不是 QQ 登录密码）
   - **SMTP 服务器**：个人邮箱 `smtp.qq.com`；企业邮箱 `smtp.exmail.qq.com`
   - **SMTP 端口 / 加密方式**：默认 `465` + `ssl`；如果改用 `587`，把加密方式改成 `starttls`
3. 开启沙盒邮件能力（默认关闭）：

   ```toml
   [sandbox]
   allow_email = true
   ```

   也可以在后台群设置里把「沙盒邮件」设为允许，只对某个群开放；单群覆盖优先于全局。
4. 在「Agent → 允许调用的工具」或单群详细设置里勾选 **发送邮件** (`email__send_email`)。

## 智能体工具

| 工具 | 说明 |
| --- | --- |
| `email__send_email` | 发送纯文本邮件。`to` 可填 QQ 号或完整 QQ 邮箱，多个收件人用逗号/空格/分号分隔；留空发给当前发言人 |

示例请求：

```
把今天讨论的结论整理一下，发到我的邮箱
把这份清单发到 123456@qq.com
给 123456 和 654321 发邮件，主题是「周末安排」，正文是……
```

工具调用需要群友 **明确要求发邮件**，并提供主题和正文。自动参与、群友互聊、含糊请求不会发送；
即使模型试图调用，宿主沙盒也会以 `automatic_side_effect` 拒绝。邮件发送成功后，模型只应说明
发送给了谁，不应在聊天里重复邮件正文。

## 配置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 发件邮箱 | 空 | 必填；发件 QQ 邮箱地址 |
| SMTP 授权码 | 空 | 必填；QQ 邮箱生成的授权码，保存后接口返回打码 |
| SMTP 服务器 | `smtp.qq.com` | 个人 QQ 邮箱 / QQ 企业邮箱（`smtp.exmail.qq.com`） |
| SMTP 端口 | 465 | SSL 常用 465，STARTTLS 常用 587 |
| 加密方式 | `ssl` | `ssl` 或 `starttls` |
| 发送超时（秒） | 15 | 5–30；低于工具超时，避免发送结果不确定 |
| 允许的收件域名 | `qq.com` | 默认只允许 QQ 邮箱；可加多个域名 |
| 单封最多收件人 | 5 | 1–20 |
| 正文最大字数 | 5000 | 100–20000；超限直接拒绝 |

## 沙盒与安全

- 工具声明 `email.send`，风险级别为 `write`。默认 `allow_email=false`，需要管理员显式开启；
  网络总开关关闭时同样无法发送。
- 自动参与（未 @、未使用唤醒词）不会执行邮件发送；单群可用「沙盒邮件」单独收紧或放宽。
- 收件人默认只允许 `qq.com` 域名，可通过「允许的收件域名」调整；QQ 号必须先通过 5–12 位数字校验。
- 当前消息必须明确提到邮箱/邮件（或直接写出完整邮箱地址），否则拒绝发送（`email_request_missing`），
  避免模型把上一条请求带进一句无关的“妈妈”里补发。
- 收件人必须有依据：`to` 只能填当前消息正文里明确出现的 QQ 号/邮箱，或当前消息 @ 到的成员；
  “发给我”必须留空 `to`，插件会使用当前发言人的 QQ。模型从聊天记录里猜出来的地址会被拒绝
  （`email_recipient_not_requested`），避免把悄悄话发给别人。
- 邮件为纯文本，不支持 HTML、附件、抄送/密送；一次最多 5 个收件人（可调）。
- 授权码按插件密钥保存，管理接口只返回 `******`；插件不会把授权码、正文或完整异常写入日志。
- 邮件通过 SMTP 直接发出，不受 `allowed_hosts` 网页主机白名单影响；但发件服务器只能从插件提供的
  QQ 邮箱服务器中选择。
- 请遵守 QQ 邮箱的发信频率限制；被服务商限流或判定为异常登录时，发送会失败并返回通用原因。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| `email_not_configured` | 还没填发件邮箱或授权码；按「准备」第 1–2 步配置 |
| `email_auth_failed` | 授权码无效或 SMTP 服务未开启；重新生成授权码 |
| `email_disabled` | 沙盒邮件能力未开启；设置 `[sandbox].allow_email = true` |
| `email_request_missing` | 当前消息没有要求发邮件；不要凭上一条消息补发 |
| `email_recipient_not_requested` | 模型填了当前消息里没出现的地址；让它留空 `to` 或先问清收件人 |
| `automatic_side_effect` | 消息不是明确请求；让群友 @ 机器人或使用唤醒词明确要求 |
| `email_recipient_domain_denied` | 收件人不是允许的域名；默认只允许 `@qq.com` |
| `email_send_failed` | 网络、端口、加密方式或服务商限制；检查 SMTP 端口/加密方式与网络 |
