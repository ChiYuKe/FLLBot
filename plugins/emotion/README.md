# emotion

> 插件包：`emotion` · 包头以 [plugin.toml](plugin.toml) 为准。

让机器人在群里有一点自己的情绪，也让它在群友正聊天时，偶尔发一条只有对方能看到的
**群临时会话（私聊）**：可能是牢骚，也可能是一句悄悄话，默认写到两到四句。对方回复私聊后，
还会打开一段互聊窗口，在窗口内像朋友一样接着聊。没有配置模型时也能工作，会改用内置的情绪化短句。

## 安装与启用

把整个 `emotion/` 目录放进配置的插件目录（默认 `plugins/`），启动 FLLBot 或等待热重载：

```powershell
.venv/Scripts/python.exe -m fllbot plugin install path/to/emotion --root .
```

插件默认启用。需要在「插件 → emotion」里确认所在群没有被单独停用；群聊默认受宿主群开关控制。
如果只想让部分群有情绪，先全局关闭插件，再在目标群单独开启。

群临时会话由 NapCat/QQ 决定：机器人必须是群成员，群设置里要允许临时会话，否则发送会失败
（日志只记录错误类型，不会反复重试）。好友私聊可在配置里把 `delivery` 改为 `private`。

## 命令

| 命令 | 说明 |
| --- | --- |
| `/情绪`（`心情` `mood`） | 查看当前群的心情、精神和最近的触发原因，以及今天的悄悄话额度 |
| `/情绪 重置` | 超级管理员重置本群情绪 |
| `/悄悄话`（`私聊` `whisper`） | 查看悄悄话状态和开关方式 |
| `/悄悄话 关闭` | 不再接收这个机器人账号的悄悄话（按用户、跨群生效） |
| `/悄悄话 开启` | 恢复接收 |
| `/哄哄`（`夸夸` `摸摸`） | 哄一下机器人，心情会变好；每人 60 秒冷却 |

## AI 工具

- `emotion__read_mood`：读取当前群的心情、精神、最近原因和悄悄话额度。只读，不会发消息。
- `emotion__send_whisper`：给当前发言人发一条临时会话，声明 `qq.send` 能力；只能由群友明确要求时使用，
  自动参与时会被拒绝，同一用户 10 分钟内最多一次，不能指定别人；发送同样消耗每群/全局每日额度。

两个工具都需要在「智能体 → 允许调用的工具」（或单群详细设置）里勾选后模型才看得到。
勾选 `read_mood` 后还会启用插件提供的一段提示词：让模型知道它现在有情绪、可以顺着情绪说话，
并减少客服腔和模板腔。这只是语气约束，不会给模型额外权限。

### 直出确认

`emotion__send_whisper` 在悄悄话确认送达后返回 `silent: true` 与一句简短的 `reply`
（“悄悄话已经说给你啦”），宿主可据此直接发送确认、省掉一次模型往返。未明确请求、额度/冷却限制、
机器人离线、生成失败或发送失败时不会返回 `silent`/`reply`，仍由模型如实说明；原有的 `sent`、
`text`、`kind` 等字段保持不变。

## 悄悄话之后的私聊互聊

悄悄话确认送达后会打开一段**私聊互聊窗口**（`chat_window_minutes`，默认 20 分钟，设为 0 关闭）：

- 窗口内的文字、图片和表情由插件沿用同一段对话历史接话：模型快聊，**不提供任何工具、不走智能体**，
  像熟人随口聊，一般两三句以内；
- 图片按主程序的图片输入设置处理，无法提供图片内容时以文字标记接话；
- 群临时会话的回复带来源群号。若协议端未提供群号，仅在窗口内能确认唯一来源群时补齐；
- 上下文只带这条悄悄话之后的私聊历史，不会翻很久以前的旧账；
- 回复走宿主统一的轮次与投递记录（分段、长回复、追踪都和智能体一致），模型失败时静默收尾；
- 窗口从悄悄话发送记录恢复，机器人重启后短时间内私聊仍能接上（最多回溯 120 分钟）；
- 超过窗口时长、`/悄悄话 关闭`、或插件/私聊总开关不允许时，私聊不再被接话；
  群里的 @、命令和智能体行为完全不受影响。

## 配置

绝大多数配置在管理端「插件 → emotion」里修改；标记“群”的项支持按群覆盖。

| 配置项 | 默认值 | 群覆盖 | 说明 |
| --- | --- | --- | --- |
| `enabled` | 开 | 是 | 关闭后本群不记录情绪，也不发悄悄话 |
| `whisper_enabled` | 开 | 是 | 只关主动私聊，保留情绪记录 |
| `style` | `mix` | 是 | `whine` 只发牢骚，`secret` 只发悄悄话，`mix` 按心情混合 |
| `probability` | `35` | 是 | 每个满足间隔和额度的群，每次轮询的尝试概率（%）；`0` 等于不主动发 |
| `min_interval_minutes` | `45` | 是 | 同一个群两次悄悄话的最小间隔 |
| `active_window_minutes` | `20` | 否 | 只挑最近这段时间内在群里说过话的人 |
| `min_messages` | `3` | 否 | 时间窗内至少这么多条消息才考虑，避免死群被点名 |
| `per_user_cooldown_hours` | `24` | 否 | 同一用户两次收到悄悄话的最小间隔，跨群共用 |
| `daily_limit` | `3` | 否 | 每个群每天最多发送条数；`0` 为不限 |
| `global_daily_limit` | `8` | 否 | 单个机器人账号全部群每天最多发送条数；`0` 为不限 |
| `quiet_hours` | `00:30-07:00` | 否 | 安静时段不主动发；按北京时间，支持跨午夜，留空关闭 |
| `max_chars` | `150` | 否 | 悄悄话最长字数（默认够写两到四句），模型输出和本地句子都会裁剪 |
| `chat_window_minutes` | `20` | 否 | 悄悄话送达后的私聊互聊时长（分钟）；窗口内私聊由快聊接话，`0` 关闭互聊 |
| `llm_enabled` | 开 | 否 | 关掉或模型不可用时使用内置短句 |
| `include_context` | 开 | 否 | 是否把最近几条群聊交给模型作背景 |
| `archive_history` | 开 | 否 | 把悄悄话写入私聊历史，方便群友私聊回复时接上前文 |
| `delivery` | `temp` | 否 | `temp` 为群临时会话；`private` 为普通好友私聊 |
| `persona` | 空 | 否 | 生成悄悄话使用的人格名；留空沿用本群或默认人格 |
| `mood_decay_minutes` | `45` | 否 | 情绪回落到基线的半衰期，避免一次夸奖影响一整天 |
| `only_interacted` | 开 | 否 | 只挑最近和机器人说过话（@、唤醒词、命令或私聊）的群友 |
| `interaction_window_days` | `30` | 否 | 多少天内和机器人说过话才算符合条件；私聊互动对所有群生效 |

## 它是怎么选的

1. 每条群消息先经过确定性规则更新情绪和活跃度：被夸、被凶、被复读、深夜、被 @、被戳都会轻微影响心情；
   情绪按 `mood_decay_minutes` 缓慢回到基线。
2. 每 60 秒检查一次（启动后先等 90 秒）。只有本群有最近活跃、插件/群开关/私聊总开关都允许、
   不在安静时段、没超过同群间隔和每日额度时，才进入下一步。
3. 在活跃时间窗内先筛掉从没和机器人说过话的人（默认要求最近 30 天内 @、用唤醒词、发命令或私聊过，
   可在配置里关闭），再按发言条数和新鲜度给剩下的人加权，排除自己、已关闭悄悄话的人和仍在个人冷却中的人；
   能在多个人里选时尽量不连续选同一个人。
4. 按心情选择“牢骚”或“悄悄话”，先用当前人格和最近群聊让模型生成两到四句、结尾带一句想听 TA 说说的
   短段；模型不可用、输出不合格或超时就改用内置句子。
5. 通过 `send_private_msg` 发送，`temp` 模式带上 `group_id` 走群临时会话；失败只记录错误并进入冷却。
6. 发送成功即打开私聊互聊窗口：窗口内对方的文字、图片和表情在智能体之前由模型快聊接话，
   超过 `chat_window_minutes` 就不再接。

情绪和活跃度分开：情绪会跨轮次保留，活跃度只在内存里保留最近 120 条消息，重启即清空。

> 互动记录从插件启用后开始累计：安装前群里已有的 @、命令或私聊不会回溯。刚装好时可能需要群友
> 先和机器人说一句话，自动悄悄话才会开始考虑这个人。

## 权限与隐私

- 发送前依次检查：插件总开关/群开关、群是否启用、`permission.allow_private`、本群配置的 `enabled`
  和 `whisper_enabled`。任何一项不允许都不会发。
- 只给**最近和机器人说过话、且正在同一个群里发言**的群友发，不翻通讯录、不跨群拉人。
- `/悄悄话 关闭` 后该用户不会再收到这个机器人账号的悄悄话；重新开启前一直有效。
- 有安静时段、同群间隔、个人冷却、每群/全局每日上限五层限制，默认节奏很克制。
- 私聊互聊只在悄悄话送达后的 `chat_window_minutes` 内生效，接收文字、图片和表情。快聊不提供工具，
  不执行操作，也不能越过私聊总开关或插件开关；`/悄悄话 关闭` 会同时关掉尚未过期的互聊窗口。
- 日志只记录群号、用户号、发送结果和错误类型，不打印悄悄话正文；正文只写入插件自己的发送记录
  和（可选的）私聊历史。
- 模型生成时默认只带最近 6 条群聊的短片段；可在配置里关闭 `include_context`。

## 数据与依赖

无额外 Python 依赖。运行数据位于 `data/plugins/emotion/emotion.db`（SQLite，WAL）：

- `moods`：按 `self_id + group_id` 保存心情、精神和最近原因；
- `whispers`：发送记录，用于冷却、每日额度、避免复读和审计，保留 30 天；
- `optouts`：用户关闭悄悄话的设置。

配置仍由宿主数据库保存。删除插件不会删除上述数据；完整备份实例时请一并保存 `data/plugins/`。
